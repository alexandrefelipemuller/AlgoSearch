## 101. Scalar-loop index range: can the piece replace `average`? -- design and predictions registered before implementing

between them. That is accepted for a removal test; a follow-up can split
them if it matters.

## 102. Nested placement piece (`--nested-place`): can the combinator replace `selectionsort`? -- design and predictions registered before implementing

Section 99 kept `selectionsort` by an exact -2 on min_gap (10 -> 8, both
misses wall timeouts). Without the skeleton, sorting is still found, but
only as an exchange sort (`SwapIf` on a nested loop). The selection family
(an inner arg-best, then one swap per outer iteration) disappears. The
combinator already has both halves: the arg-best update (section 82) and
the nested loop with a per-outer reset/consume (section 71). What is
missing is a consume that *acts on the array* with the arg.

**The piece.** A new variant inside `Relation::Nested`, drawn first in that
case with probability 1/3 only when `GenConfig::nestedPlace` is on (so the
stream is byte-identical off). On a nested loop over one sequence:
    t = i                               (per-outer reset; t is `found`)
    inner: if (elem(j) CMP elem(t)) t = j   CMP in {<, >, <=, >=}
    per-outer: swap(elem(i), elem(t))
No write-back. Loop shape stays the combinator's own draw, so the
triangular variant (j = i + 1) is selection sort ascending or descending
and the full variant is a different, mostly wrong program. Name:
"place the best of the rest at i". It is the arg-best of section 82 with
a placement consume instead of an aggregate, not a new skeleton.

CLI: opt-in `--nested-place`; becomes the default only through the rules below.

## 104. Matrix relaxation piece (`--combinator-relax`): can the combinator replace `graphreachability`? -- design and predictions registered before implementing

Section 99: graph_reachability is 10/10 with its skeleton and **0/10**
without it. Both graph skeletons (reachability, shortest path) are one
shape: a header V = arr[0], a state vector S[k] = arr[1 + k], a V x V
matrix M[i][j] = arr[1 + V + i*V + j], and a fixed point: V rounds of
"for every (i, j): if guard(S[i]) and edge(M[i][j]) then update S[j]",
then arr[0] = S[V-1]. Mini-C has no queue, so relaxation rounds stand in
for BFS (section 16).

**The piece.** A combinator block drawn first in `genCombinatorBlock` with
probability 1/8, only when `GenConfig::combinatorRelax` is on and three
loop slots are free (byte-identical off). Parts drawn independently:
- Init: S[0] = 1 (rest stays 0); or, with four loop slots, every S = 100000
  then S[0] = 0.
- Guard on S[i]: none, `S[i] == 1`, `S[i] != 0`.
- Edge test on w = M[i][j]: `w == 1`, `w > 0`, `w != 0`.
- Update: `S[j] = 1`; `S[j] = S[i]`; `if (S[i] + w < S[j]) S[j] = S[i] + w`;
  `if (S[i] + 1 < S[j]) S[j] = S[i] + 1`.
- Output: arr[0] = S[V-1]; with the INF init, half the time
  `-1` instead when S[V-1] is still 100000.
Graph reachability is several draws (init 1, guard `==1` or `!=0`, any edge
test, update `= 1`), about 1/12 of blocks. Shortest path (INF init, guard
none, edge `> 0` or `!= 0`, update `+ w`, -1 output) is also in the family,
but its skeleton is not a target here (not in the joint battery list).

**Predictions.**
1. Probe (forced combinator draws, numVars 8, maxLoops 4): draws solving
   graph_reachability levels 2-5 go from 0 (off) to > 0 (on).
2. A/B, 30 seeds (51000-51029), graph_reachability only: base vs GRX

## 109. Grid DP piece (`--combinator-grid`): can the combinator replace `dtw`? -- design and predictions registered before implementing

Section 107: dtw is 10/10 with its skeleton, 0/10 without. The skeleton is
one instance of a family: a DP table over two sequences, filled in row
order from the up, left and diagonal cells.

**The piece.** Layout fixed as DtwProblem's: n = arr[0], table T[i][j] =
arr[1 + i*(n+1) + j], A after the table, B after A. A combinator block drawn
first in `genCombinatorBlock` with probability 1/8 when
`GenConfig::combinatorGrid` is on, three loop slots are free and numVars
>= 11 (byte-identical off). Axes drawn independently:
- Boundary: edges INF (corner 0); edges = index (edit distance); edges 0.
- Cell cost of (a, b) = (A[i-1], B[j-1]): |a - b|; a != b ? 1 : 0;
  a == b ? 1 : 0.
- Recurrence: cost + min(up, left, diag); min(up + 1, left + 1, diag +
  cost); max(up, left, diag + cost).
- Output: arr[0] = T[n][n].
27 draws; DTW is one (INF, |a-b|, cost + min). Edit distance and LCS are
also single draws, but no benchmark problem uses them, so generality beyond
dtw is shown only in the probe. This is the most problem-shaped piece so
far; honest framing: a parametrized family of three textbook DPs.

**Predictions.**
1. Probe (forced combinator draws, numVars 12, maxLoops 4): draws solving
   dtw levels 1-4 go from 0 (off) to > 0 (on).
2. A/B, 30 seeds (55000-55029), dtw (max-n 5, num-vars 12, wall 300):
   base vs DPX (`--combinator-grid`, `dtw` off). DPX >= base - 3, and >= 27
   if base is 30/30.
3. Usage map: only dtw winners use a grid DP.
4. If 2 holds, joint battery (73 x 10), step 6.

## 111. Per-term transform piece (`--combinator-transform`) -- registered before implementing

Target rulers (sections 80, 110: 0/10 in every battery): `sum_of_rises`
and `sum_abs_from_first`. Both are a sum of a *transformed* term, and the
combinator's sums only add the raw term (Sum: elem(i); SumStep: the step,
or |step| since section 80).

**Piece.** Two axes, drawn only with the flag on (byte-identical off):
- SumStep gains a clamp transform: with |step| not drawn, one time in
  three `if (step < 0) step = 0` (with the existing direction flip this is
  the sum of rises or of drops).
- Sum on a single loop gains a reference axis, half the time: the term
  becomes `t = elem(i) - elem(start)` (or `elem(start) - elem(i)`, half),
  then one transform of {identity, |t|, max(0, t)}.

**New problems** (written now, before running):
- predicted reachable: `sum_excess_over_first` (sum of max(0, arr[i] - arr[0]))
  and `sum_of_drops` (sum of max(0, arr[i-1] - arr[i]));
- new rulers, predicted unreachable: `sum_squared_steps` (sum of the
